# Conversation Memory Assistant

## Purpose

This document defines the system's domain.

It describes the business entities, their responsibilities and the
relationships between them, independently of any technology used
(PostgreSQL, Prisma, Anthropic, etc.).

This document represents the common language (Ubiquitous Language) used
throughout development.

---

# Domain principles

## The conversation is the source of truth

All of the system's information comes from a WhatsApp conversation.

No analysis can exist without a conversation.

---

## Evidence never changes

The original messages are evidence.

Once stored they are never modified.

They are never deleted.

They are never rewritten.

---

## Knowledge can evolve

Every interpretation made by AI can be regenerated.

Derived knowledge never modifies the original evidence.

---

## Every conclusion must be verifiable

Each analysis must be able to state which messages it used to reach a
conclusion.

---

# Domain entities

---

## Conversation

### Description

Represents a complete conversation.

In the initial version there will be only one conversation.

### Responsibilities

- Group all the messages.
- Group the participants.
- Be the system's main context.

### Contains

- Messages
- Participants
- Cases

---

## Participant

### Description

Person who takes part in the conversation.

### Responsibilities

- Identify the author of each message.
- Represent a role within the conversation.

### Examples

Organizer

Member

System (future)

---

## Message

### Description

Represents an individual message.

It is the minimum unit of evidence.

### Responsibilities

- Keep the original text.
- Keep the date and time.
- Keep the author.
- Reference attachments.

### Constraints

- Can never be modified.
- Can never be deleted.
- Can never be summarized.

---

## Attachment

### Description

File associated with a message.

### Types

- Image
- Audio
- Video
- Document
- Sticker

---

## ImportJob

### Description

Represents an import process.

### Responsibilities

- Record when information was imported.
- Allow re-imports.
- Maintain traceability.

---

## Source

### Description

Origin of the information.

### Examples

- WhatsApp Export
- WhatsApp Live (future)

---

# Knowledge model

---

## Case

### Description

Represents a continuous topic within the conversation.

A Case can last days, months or years.

It groups multiple related events.

### Examples

Trip plans

Shared budget

Work project

Health

---

## Event

### Description

Represents a fact that occurred at a specific moment.

It may involve one or several messages.

### Examples

Proposal

Acceptance

Refusal

Schedule change

Discussion

Agreement

Cancellation

Activity

---

## Insight

### Description

Represents confirmed knowledge.

An Insight can come from one or several events.

### Examples

There is an agreement to meet on Saturdays.

The proposal was rejected.

It was agreed to change the schedule.

---

## Entity

### Description

Element identified within a message.

### Examples

Person

Place

Date

Time

Institution

Activity

Money

---

## Relationship

### Description

Relationship between domain entities.

### Examples

Person → Takes part in → Event

Event → Belongs to → Case

Insight → Derived from → Event

---

# Derived Artifacts

The following elements do not represent business concepts.

They are artifacts generated by automatic processes and can be regenerated at
any time.

They have no independent lifecycle.

They are not Aggregate Roots.

They never modify the evidence or the domain knowledge.

---

## Analysis

### Description

Interpretation made by artificial intelligence.

It never represents an absolute truth.

It must always include a confidence level.

### Examples

Formality

Cordiality

Tension

Cooperation

The concrete dimensions are defined by the active domain profile (`analysisDimensions`).

---

## Observation

### Description

Preliminary conclusion obtained by AI.

It is not a fact.

It may later become an Insight.

### Example

"The conversation seems to be escalating."

---

## Embedding

### Description

Vector representation of a message or set of messages.

Its sole purpose is to facilitate semantic retrieval.

It is not part of the business knowledge.

---

## Summary

### Description

Automatically generated summary.

It can exist per:

- Day
- Week
- Month
- Case
- Conversation

---

# Assistant model

---

## Reminder

### Description

Activity that must be reminded to the user.

### Examples

Thursday's meeting.

Delivery of a document.

Pending payment.

---

## Draft

### Description

Message suggested by the system.

It is never sent automatically.

It always requires the user's approval.

---

## Suggestion

### Description

Recommendation made by the system.

### Examples

Reply in a more formal tone.

Wait before replying.

Attach evidence.

# Domain rules

## Evidence

- Is never modified.
- Is never deleted.

---

## Knowledge

- Can be recomputed.
- Can be regenerated.

---

## AI

- Never invents information.
- Always states its confidence.
- Always references evidence.

---

## Assistant

- Never replies automatically.
- Never modifies messages.
- Never deletes history.

---

# Domain goal

The goal of the system is not to store messages.

The goal is to transform conversational evidence into knowledge that can be
queried, verified and reused, always preserving the integrity of the original
conversation.
